# Помилки під час запуску бота

У цьому файлі зібрані помилки з traceback, які виникали під час роботи над ботом, їхні причини та виправлення. Значення токена сюди не записується.

## 1. Не задано `BOT_TOKEN`

**Повідомлення traceback:**

```text
RuntimeError: Задайте BOT_TOKEN у змінних середовища.
```

**Де виникла:** `app/main.py`, під час читання `BOT_TOKEN` через `os.getenv("BOT_TOKEN")`.

**Причина:** змінна `BOT_TOKEN` не була доступна процесу Python. Сам запис у `.env` автоматично не завантажувався командою `python -m app.main`. Помилка з'являлася повторно, бо команда запуску не отримувала токен зі змінних середовища.

**Виправлення:** застосунок було змінено так, щоб він сам читав `.env` із кореня проєкту. Тепер запускати його можна командами:

```bash
source .venv/bin/activate
python -m app.main
```

Перевір, що `.env` лежить у корені проєкту, містить рядок `BOT_TOKEN=...` зі справжнім токеном і не додається до Git.

## 2. Неправильна назва модуля `asyncio`

**Повідомлення traceback:**

```text
ModuleNotFoundError: No module named 'asyncioo'
```

**Де виникла:** `app/main.py`, рядок імпорту на початку файлу.

**Причина:** у назві стандартного модуля Python `asyncio` випадково з'явилася зайва літера `o` — було написано `import asyncioo`.

**Виправлення:** рядок замінено на правильний:

```python
import asyncio
```

## Як читати traceback

- Починай із останнього рядка: там вказані тип і короткий опис помилки.
- Знайди перший рядок traceback, що посилається на файл проєкту, наприклад `app/main.py`, і перевір відповідний рядок коду.
- Для помилок із конфігурацією перевір назву змінної й те, звідки застосунок її завантажує. Не вставляй токен у повідомлення чи traceback, які надсилаєш іншим.
